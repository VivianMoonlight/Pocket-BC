# Echo 本地数据更新

客户端默认直接从 [Echo GitHub 仓库](https://github.com/SugarChain-Studio/echo-clothing-ext)检查更新，在本地生成纯数据包，无需另建发布服务。新的行为仍需 APK 适配；外观数据更新不自动开放领域层的穿戴、配置或互动能力。

## 默认更新流程

首次使用 Echo 名称或立绘时，选择一个进程级数据快照，并后台检查一次 GitHub `main`。当前运行中的目录、名称、别名、适配清单和图片哈希始终来自同一版本。成功下载并生成的新包下次启动生效。

1. 读取 `commits/main`，取得完整提交号；与当前快照相同则结束。
2. 通过 GitHub compare 确认新提交在当前提交之后。分叉、回退、限流和网络错误均保留当前包。
3. 获取该固定提交的递归 Git tree，校验 tree 身份并拒绝截断结果。
4. 对照随 APK 发布的 `source-index.json`。源码及公共依赖哈希未变的复杂定义复用已审核提取结果；新增或改动的普通服饰定义下载到本地，逐个验证 Git blob 后静态解析。
5. 重建目录、名称、别名和图片白名单。删除的组件不会留下旧定义；不支持的组件记录在包的 `extractionReport.omitted` 中。
6. 通过统一的数据包兼容检查后原子安装，保留上一份有效包。日志标签为 `EchoData`。

图片按固定提交从 CDN 获取；请求失败或内容校验不符时，依次回退到同一提交的 GitHub raw 地址和 GitHub 下载入口。所有来源都必须通过图片表中的 Git blob 校验。客户端只将下载的 JavaScript 源码当作文本解析，不执行模组、导入模块或调用源码函数。

代码职责：`EchoGithubUpdate` 负责版本定位、下载与源码完整性校验；`EchoGithubCompiler` 负责组件提取、资源筛选和数据包组装；`EchoStaticSource` 只解析声明语法。解析器和包加载器共用 `EchoDataRules` 的能力边界，最终由 `EchoDataPack` 校验完整包，再交给 `EchoPackStore` 安装。编译过程不修改内置索引，图片匹配结果只在本次编译中复用。

## 本地解析范围

支持注释、字符串、数字、布尔值、null、常量引用、对象/数组、展开、对象简写、已知枚举、数值加减，以及 `AssetManager.addAsset`、`AssetManager.addAssetWithConfig` 和既有名称修正注册。typed/modular 配置中的纯数据可以更新。

旧式 `addAsset` 的扩展配置、翻译和 noMirror 参数转换为相同的数据记录；可选参数位置允许 undefined。全部图层都明确设置 HasImage=false 的资产不要求图片文件，例如透明身体通过 Hide 隐藏身体图层。未声明无图、实际需要图片的资产仍检查固定提交中的素材。

只识别完整的声明模块与 `export default function ()` 注册外壳。未知导入、函数调用、循环、赋值、回调、原型键和未知动态字段不能混入提取结果。函数生成的数据可在源码和依赖哈希未变时复用 APK 内的审核结果；变化后若静态解析不支持，会排除该组件。

身体组、既有武器组合、互动标记、绘制适配器所在文件，以及许可、公共生成器、注册库依赖发生变化时，整次更新停止，等待客户端审查。这些边界宁可保留旧包，也不根据不明行为猜测新数据。原始许可和附录随包保留；收录候选不再按文件名或套装目录排除。

构建时支持固定版本 DialogTools 的 repeatEntries、combine、showHide 和 autoItemStrings 纯文案生成器，避免头套等外观因为编辑器文案依赖而整组件漏收录。手机更新复用哈希未变的提取结果，不执行这些函数；utils 依赖改变仍要求客户端审核。可运行 `node scripts/verify-echo-dialog-tools.mjs PINNED_UTILS/src/Tools/dialogs.js` 对照上游，检查输出和输入不变性。

限制：单个源码文件最多 512 KiB，最多下载 128 个变化文件、合计 16 MiB；递归 tree 最多 12 MiB，最终包最多 12 MiB。未知组或原版资产重名会排除普通组件；普通组件中缺图的资产单独排除，并同步移除名称及别名，其余资产保留。已要求审核的组件丢失图片仍会终止更新。结构校验不保证所有新素材的视觉效果，新增复杂格式仍需测试和代码适配。

## 维护内置基线

当前内置基线在同一 Echo 提交上收录 251 个组件、719 个组内资产记录、23903 张上游图片。候选目录覆盖衣服和装饰、束缚与玩具、家具及摆设、套装、工具和后背组件。图片包括新增资产及 Echo 对原生身体、衣服和道具的替换素材；原生资产身份保持不变，匹配的图片路径按固定提交和哈希加载 Echo 版本。动态更新采用相同筛选规则，包括按体型命名的空名称手臂和手部资产。资产记录按身体组计数，同一衣服出现在多个组时会计为多条。

原生 ItemTorso 与 ItemTorso2 双向注册同一道具，noMirror 可禁止复制；名称修正规则按 Echo 自身的单向规则处理。自定义复制组继承源组的图片组、已适配绘制回调和扩展配置，再注册专属资产，供后续复制组继承。复制出的资产定义独立且价格为零，显式提供的资产列表保留原值。这里只实现立绘所需语义，未开放资产管理器的交互菜单和游戏行为。

当前穿搭显式选入的五类资产绑定组件源码哈希。旗袍、发卡和丝袜直接使用静态定义；乳胶衣剥离编辑界面的复制颜色回调。眼睛保留 Daydream／Dizzy 图片映射，不显示的图层使用本地透明像素；构建提取和手机重建均将映射目标图片纳入哈希索引。

自动闭腿是 Visible=false 的行为工具，在只读立绘中保留无图身份，避免误报外观缺失；不安装其 ScriptDraw，也不改变传入姿势或发送姿势更新。该组件源码变化要求重新审核。它的游戏内自动改姿势功能不属于这项立绘识别支持。

左右遮罩使用 APK 内固定的 250×1000 不透明黑色图片，保留上游 `SockLRTool` 的位置、姿势和混合模式。生成器源码列入依赖哈希检查；遮罩不需要联网下载，也不执行上游的动态画布注册逻辑。

咬痕的已审核编辑界面回调在构建时剥离，保留位置开关和图层数据；标志纹饰由客户端按姿势、部位开关计算遮罩。组件源码与相关辅助库仍受哈希约束，上游行为变化后需重新审核。

运动套装的文字子配置通过已审核的嵌套 `AfterDraw` 适配绘制弧形文字，保留体型对应的宽度、偏移及字体配置；其余套装部件按静态数据渲染。数据包不能自行添加回调路径或行为。

狗机仆头套通过独立的文字子配置适配，保留 80×48 画布、字体、弧度及位置偏移，支持改字、空文字和关闭文字。适配绑定组件源码哈希；客户端拒绝数据包任意层级残留的 ScriptHooks，只安装审核清单指定的回调。

身体论文通过 15 个文字子配置绘制，不依赖图片。复制身体组先继承原组资产，再注册专属外观；扩展配置独立保存，避免写回原组。文本使用配置的字体名称，未安装或加载的字体仍会由 WebView 回退。

单渐变和双渐变使用客户端内置的头发遮罩与渐变绘制代码，保留前后发开关、渐变位置、大小和旋转参数。遮罩图片进入现有缓存加载流程；图片未完成时重绘，不提前报告完整结果。

交领右衽的延长及仅边线样式使用内置 WebGL2 着色器，按身体、衣服和手臂遮罩裁剪。图片尚未加载时交给现有缓存重试；该效果需要 WebView 支持 WebGL2。

油光袜的剪裁遮罩在本地按需合成，保留原生图片缓存的解码、失败和清理状态。120 种姿势、体型和剪裁配方与固定版本上游一致。

逐件渲染检查还修正了三处固定版本数据：BodyMarkings 组的脚趾甲继承下半身体型，猫爪围裙的手臂遮罩映射到 ClothAccessory，玩偶把手的四肢着地图层仅在 AllFours 姿势加载。这些修正绑定组件源码哈希；动态更新遇到对应源码变化时要求重新审核，避免继续套用过期修正。完整目录检查的运行方法和验证范围见 [立绘 dump 与重放](portrait-dump.md)。

全包毛毯 Small 体型的后层图片使用上游实际存在的“后 - 副本”文件；路径修正绑定组件源码哈希，并对两个躯干区域分别验证。

食物、新眼睛和落落发饰组件不再只保留指定子集：静态食物、其他眼睛和树叶发饰也一并提取，名称、别名及图片映射完整保留。既有审核组件的源码哈希边界仍保持，源码或许可变化后的审查规则不变。

打包工具生成 `pack.json` 和 `latest.json`；清单包含 `format: 1`、递增的 `sequence`、包的 `url` 和 `sha256`。替换示例中的仓库信息，先发布包再发布清单。清单与包必须来自同一 HTTPS 主机，不能带凭据、查询参数或自定义端口，请求不跟随重定向。GitHub Releases 下载链接通常需要重定向，应使用能直接返回 JSON 的地址。SHA-256 提供完整性校验，不是发布者签名；此配置应指向可信来源。
