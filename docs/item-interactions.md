# 道具交互验证

单件发送会在实际 emit 成功后更新发送者的本地外观；原生 BC 不向发送者回传该更新。这个刷新不等于接收者接受，接收者仍会执行解包和外观校验，并可能发回修正。

R133 角色快照中的 `PermissionItems` 按资产保存整件权限与 `TypePermissions`。Socket 映射把它分解为领域已有的禁止、有限和收藏列表；新字典存在时覆盖旧列表，即使字典为空。不会把 Limited 当成 Block，也不会把单个模式的限制扩大为整件限制。旧版本保留旧列表读取方式。

`core/socket/src/test/resources/bc-item-wire-r133.json` 同时用于发送序列化测试和原生接收端检查。原生检查运行官方 R133 的物品解包、扩展属性初始化及 `ValidationResolveAppearanceDiff`，强制发送者与佩戴者不同；覆盖穿戴、模式切换、拆卸及禁止道具/禁止模式的拒绝。

运行方式（仓库根目录，使用 Node 和 Chrome）：

```powershell
# Server.js 须来自固定 R133，检查器会校验 SHA-256。
curl.exe -L https://www.bondageprojects.elementfx.com/R133/BondageClub/Scripts/Server.js -o _local-artifacts/relationship-Server.js
$env:BC_ITEM_INTEROP_OUT = '_local-artifacts/native-item-receiver.json'
node scripts/verify-portrait.mjs
.\gradlew.bat testDebugUnitTest assembleDebug
```

检查只导入 Server.js 的物品解包和颜色解析函数，不启动账号网络逻辑。运行时使用合成角色与普通房间状态；GGTS、日志和 ItemScript 权限标签是测试环境桩，因此不证明这些玩法及规则兼容。它也不证明真实服务器、所有道具、手机 WebView 或图片资源已全面通过。

## 试穿预览

聊天中的道具和服装选择器为穿戴、替换及模式行提供预览入口。预览从已验证在线、当前房间内的角色快照生成临时外观；模式预览保留当前颜色、难度、制作信息和已合成的文字属性。角色、账号或房间来源变化会关闭旧预览。它不调用道具执行接口，也不更新真实穿搭。

图像由现有 R133 原生／Echo 静态绘制器显示，打开弹窗后直接展开；沿用缺图、部分支持、失败和重试提示。其他 BC 版本及未适配的动态脚本仍受原绘制器限制，预览入口不代表相应操作已支持。

```powershell
$env:ITEM_TRYON_PROBE_OUT = '_local-artifacts/item-tryon-pixels'
node scripts/verify-portrait.mjs
```

输出目录必须不存在。检查完整角色下原生麻绳默认模式、另一模式和 Echo 简单绳的画布，要求图像可见、没有遗漏图片、模式像素不同，并验证恢复原快照后图像一致。输出 PNG 和诊断报告；不覆盖 Compose 弹窗、全部道具或 Android WebView。

## 文字道具

静态 Text 架构读取 `MaxLength` 和文字初始值，常见木牌、电子名牌等可以默认穿戴，并从当前物品卡片进入文字编辑。模块道具中始终存在的单选项 Text 子界面也可使用这个入口，例如 CustomCollarTag；带有条件切换或自定义校验的子界面仍需单独适配。允许绘制钩子；自定义初始化、校验、事件监听或特殊发布流程不作为普通文字道具开放。

编辑器遵循原生 `DynamicDrawTextRegex` 和 UTF-16 长度限制，支持中文、数字、空格与半角标点，以及清空。表情、换行、超长内容在本地阻止保存；这些限制只作用于原生文字输入字段，不改变制作名称及描述的原样显示。保存只覆盖声明的文字字段，其他属性、颜色、难度和制作信息沿用当前物品。角色或部位变化会关闭旧编辑器，取消后重开读取实际文字；锁具和权限仍经领域及最终发送校验。

模块属性合成遵循 R133 ModularItemSanitizeProperties 对 Text、Text2 和 Text3 的处理，保留有效字符串并忽略无效值。切换形状以当前文字作为基线，再合成选中模块，避免将编辑后的内容重置为默认文字。文字入口独立检查当前物品的修改权限，不再取模式列表第一行的启用状态；第一行是当前选项时，仍可编辑文字。

发送序列化与原生接收端共用的测试数据另覆盖中文木牌穿戴、已有文字清空，以及模块名牌变形时保留中文文字，检查接收端没有替换文字。领域与列表测试覆盖默认值、长度及字符限制、制作信息保留、禁止编辑、空行次序和自定义钩子不误开放。

```powershell
node scripts/verify-modular-text.mjs
```

模块文字检查器校验固定官方 R133 ModularItem.js 和 DynamicDraw.js 的 SHA-256，运行实际合成及清理函数，与 Kotlin 共用 6 个用例，覆盖默认文字、中文保留、选项覆盖、空字符串、多文字字段及无效值。

## 密码解锁

PasswordPadlock、SafewordPadlock、TimerPasswordPadlock 和 CombinationPadlock 提供密码输入；持有钥匙时也保留独立的密码入口，以便选择密码解锁及其拆除行为。密码按原生规则转大写比较，数字组合保留前导零；尝试输入不会作为聊天内容、动作词典或物品属性发送。错误输入显示本地提示，不调用交互发送接口。列表只开放输入入口，不提供携带已存密码的候选或可执行命令。

正确密码解锁保留物品的模式、文字、颜色、难度及制作信息。密码锁的 `RemoveOnUnlock` 为真时会同时拆除物品；定时密码锁的 `RemoveItem` 仅控制计时结束行为，不作为密码开锁时拆除的依据。有可用钥匙时仍使用原有钥匙解锁流程。

输入仍受物品／锁具限制、关系权限、部位可达性及服务端 AllowItem 校验约束。密码输入与物品快照绑定；目标、部位或锁具变化后，旧对话框及等待发送的操作失效。原生密码开锁允许手部受限，钥匙开锁保留其原有手部检查。

组合锁支持失明和手部受限时的拨码：本次检查中的失明偏移保持固定，手部受限时对新输入的每个数字增加随机偏移，删除和未改动的数字不重复偏移。当前码与新码沿用原生共享输入历史的规则。输入框在失明时遮盖数字，并显示相应操作提示。`IsRestraint` 按原生资产、组继承及 Appearance 类别覆盖规则解析，用于计算手部灵巧度；制作 Thick／Thin 效果计入视力限制。普通密码输入在失明时仍仅对 SafewordPadlock 开放。双眼闭合时保守计入视力限制，因为本地闭眼失明偏好不在房间快照中。

R133 接收端检查另覆盖他人密码解锁保留模式和解锁拆除物品。锁具用例使用允许上锁的 LeatherCuffs，并在执行变更前验证旧锁有效；不再使用不允许上锁的 HempRope 模式。领域与界面状态单元测试覆盖错误密码、数字组合前导零、无钥匙输入、受限视力、禁止锁具、旧快照和实际发送前密码变化。手机密码键盘、焦点、弹窗及真实在线同步仍未验证。

```powershell
node scripts/verify-lock-input.mjs
```

此脚本校验固定官方 R133 CombinationPadlock.js 的 SHA-256，只提取其输入处理函数，在 Node VM 中运行合成输入，不启动账号或网络逻辑。它与 Kotlin 测试共用 `combination-input-r133.json`，验证普通输入、失明偏移、随机偏移、粘贴、删除、替换及两个输入框共享历史的结果。

## 锁具设置

未确认的密码锁、SafewordPadlock 和定时密码锁提供密码与提示设置入口，沿用原生 `LockSet` 和上锁者判断。留空保留原密码／提示，密码转大写并校验为最多 8 个英文字母，提示按 UTF-16 限 140 个字符；额外防止大写转换扩展后超过接收端长度上限。普通密码锁可同时设置密码解锁时拆除道具，定时密码锁不提供该选项。确认后不再开放重新初始化，须先解锁、重新上锁。

组合锁提供当前码与新码输入，核对当前码后只更新四位数字组合，保留锁具身份、模式、制作信息及未知道具属性。设置成功使用原生 PasswordChangeSuccess／CombinationChangeSuccess 消息，聊天词典不含密码或组合码；新密码／组合码仅作为必要的物品属性同步。目标或锁具变化、权限变化及等待发送期间另一端已确认密码时，不覆盖新状态。

接收端共用用例覆盖对他人设置密码、中文提示、拆除选项及组合码前导零；领域与界面状态测试覆盖创建者、重复确认、长度和字符限制、空值保留、不可上锁模式、部位和锁具权限、过期输入，以及等待发送时锁具变化。

## 计时锁编辑

TimerPadlock、OwnerTimerPadlock、LoversTimerPadlock、MistressTimerPadlock 和 TimerPasswordPadlock 提供计时设置入口。普通计时锁可以重新计时，上锁者可设置到期拆除；其他四种支持增减时间、到期拆除、显示时间和公开参与。主人计时锁由主人设置，恋人计时锁由主人或恋人设置，女主人计时锁由上锁者设置、上锁者或有效 ClubMistress 身份调整时间，定时密码锁由上锁者设置。公开参与开启后，无直接调时权限的角色可以按原生幅度增加、减少或随机调整一次；参与名单按实际发送保存，即使本次被上限截断也不能重复使用。

剩余时间按服务端时间锚每秒更新。隐藏时间不会传入界面状态；主人／恋人的原生查看权、失明、手部受限及定时密码锁的部位可达性分别检查。手部受限可查看，但不能保存设置或调时。已到期或时间锚缺失时不开放修改。弹窗绑定目标和部位，切换目标后旧操作失效。

调时选项来自原生分钟、小时和天列表。实际发送时重新计算时间与上限，线上其他佩戴者的 LockTimerLimit 覆盖资产上限；给自己调时沿用资产上限。基本计时锁重启使用资产初始时长。缺省属性沿用原生初始化，显式 null 不被默认值覆盖。只修改计时字段与必要的 Lock 效果，保留文字、模式、颜色、难度、制作信息和未知属性。公开动作按实际增减量生成，隐藏计时不发送时长；没有实际增减时不发动作。等待发送期间目标、权限、锁属性、私有身份日志或计时状态变化会拒绝旧操作。

```powershell
node scripts/verify-timer-edit.mjs
$env:BC_ITEM_INTEROP_OUT = '_local-artifacts/native-timer-editor-receiver.json'
node scripts/verify-portrait.mjs
.\gradlew.bat testDebugUnitTest assembleDebug
```

原生计时检查器校验五份固定 R133 锁具脚本的 SHA-256，运行实际点击及调时函数，与 Kotlin 共用 16 个计时用例。接收端共用用例包括给他人设置计时标志，以及非主人通过公开参与修改时间和名单。单元测试另覆盖角色权限、到期边界、默认值、复制资产的上限、排队期间时间和偏好变化、隐藏计时、旧目标和实际发布词典。手机计时弹窗、真实在线双客户端和后台计时仍未验证；这些入口不代表 AFC 私有计时器已适配。

## 高安全锁钥匙名单

HighSecurityPadlock 支持从当前物品卡片编辑钥匙持有人。原生规则要求操作者已在名单内，不要求是上锁者；部位被阻挡或操作者失明时禁用入口。设置受物品权限和服务端 AllowItem 校验约束。AFC 心形锁和 R132 公开摘要识别出的旧式心形锁保留独立协议，不开放这个原生设置入口。

名单输入最多 250 个 UTF-16 字符，以逗号分隔。沿用原生 Number 转换，过滤无效条目并按首次出现顺序去重，支持已有指数和进制形式编号。保存替换名单，可选择追加操作者自己的主人、恋人和白名单；主人和恋人默认勾选，白名单默认不勾选。钥匙寄存生效时先移除输入名单里的操作者编号，再执行所选追加。空／缺失名单按原生初始化从上锁者恢复；异常的非字符串真值不会授予编辑权。保存保留锁具身份、文字、模式、颜色、难度、制作信息和未知属性，随后发送原生 HighSecurityUpdate 动作。

原生钥匙解锁也采用相同的编号读取方式，并按当前服务端时间排除已经过期的寄存记录。正好到期时仍视为寄存有效，没有时间锚时保守保留寄存限制。排队期间钥匙名单、操作者关系或寄存记录变化会拒绝旧保存。

## 自动到期

会话运行层在线进入房间后检查自己佩戴物品的 `RemoveTimer`，不依赖打开道具面板。使用服务端时间锚与单调时钟推算当前时间，不使用用户设备的日历时钟。没有可用时间锚、会话未验证在线或自己不在当前房间时不发送；重新进入有效会话后会补处理已到期的物品。其他在线角色的到期操作由其客户端负责。

到期按原生 TimerInventoryRemove 处理：清除锁与计时属性，保留模式、文字、颜色、难度、制作信息及未知属性；`RemoveItem` 为真时拆除物品。这是佩戴者的计时结算，不要求钥匙、可用双手或 AllowItem。属性名按原生大小写精确匹配，`removeTimer` 等自定义字段不触发结算。解锁清理遵循 ValidationDeleteLock，保留显式 null、自定义同名小写字段及不是精确 `Lock` 的其他效果。

每个到期更新均在实际发送前复核账号、登录代次、房间访问、所选物品与当前服务端时间。Socket 为自动到期保留原物品快照，只核对被结算的部位；同一批其他部位先完成解锁时，不会使下一件误判失效。原物品已更换或计时已延长时仍拒绝，并使用 Socket 自身的时间锚再次确认到点。快照元数据不进入发送数据。相同未确认状态的失败或重复发送间隔至少 15 秒，状态变化后重新规划。发送成功后沿用共用物品更新流程写入本地外观与待保存的账号 Appearance；锁具的 TimerRelease 消息使用原生 DestinationCharacterName／LockName 词典，在物品更新之后发布。多个锁到期逐件发送各自的消息，未使用原生 TimerReleaseMany 聚合消息。

```powershell
$env:BC_ITEM_INTEROP_OUT = '_local-artifacts/native-item-receiver-timer-expiry.json'
node scripts/verify-portrait.mjs
.\gradlew.bat testDebugUnitTest assembleDebug
```

到期检查器校验固定官方 R133 Timer.js、Validation.js 和 DictionaryBuilder.js 的 SHA-256，运行原生到期及锁属性清理函数，与 Kotlin 共用 `item-timer-r133.json`。覆盖边界时刻、未来时间、小数和指数格式的数值、非数值字段、自己的解锁／拆除、其他在线角色不由本机处理，以及文字、自定义字段和 null 保留。该函数验证使用合成角色，InventoryRemove 只模拟本部位移除，不证明 RemoveItemOnRemove 级联兼容。
